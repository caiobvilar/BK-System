# Debrief — BK-System build: mishaps, bugs, errors, fixes & decisions

Catalogue of everything that went wrong while setting up and building the
BK-System C++ banking app (SDL2 + ImGui + MariaDB) on Fedora 44 with GCC 16
using Conan 2, plus the fixes and the decisions that shaped the outcome.

Last updated: 2026-08-06

---

## 0. Hard constraint (the most important rule)

**Do NOT alter downloaded libraries** — anything from the Conan cache, anything
installed via `dnf`, or anything that ships with the OS distro. That would
require a major upstream Linux contribution that is not in scope here.

**Only the project's own libraries/modules may be refactored or fixed.**

Implication for this session: the gettext 0.26 build problem cannot be solved
by patching the gettext recipe inside `~/.conan2/`. A working fix was found
that way and is documented below for completeness, but it was **reverted**
because it violates this rule. See §4.

## 3. Category: Conan dependency build failures

### 3.1 mariadb-connector-c/3.4.3 — `typedef char bool` under C23

- **Symptom**: build error about `bool` — GCC 16 defaults to C23 where `bool`
  is a keyword; the C library code uses `typedef char bool`.
- **Fix (project-level, allowed)**: pass `-std=gnu17` to all conan builds via
  the install command line:

  ```bash
  conan install . --build=missing -c tools.build:cflags="[\"-std=gnu17\"]"
  ```

- **Status**: resolved.

### 3.2 gettext/0.26 — the deep rabbit hole

gettext 0.26 is pulled in transitively as a build requirement of
`pulseaudio/14.2` (`gettext/[>=0.21 <1]`), which is itself pulled by SDL.

#### 3.2.1 Error 1 — `_Generic` in C17-compiled gnulib headers

- **Symptom** (gettext-runtime/intl/gnulib-lib):
  ```
  ./wchar.h:856:23: error: expected identifier or '(' before '_Generic'
  ./stdlib.h:820:20: error: expected identifier or '(' before '_Generic'
  ```
- **Root cause chain**:
  1. glibc 2.40+ turns on C23 header features via `__GLIBC_USE (ISOC23)`.
  2. `__GLIBC_USE (ISOC23)` is set when `_ISOC23_SOURCE` (or `_GNU_SOURCE`)
     is defined — `features.h` lines 217-226: `_GNU_SOURCE` **forces**
     `_ISOC23_SOURCE` and `_ISOC2Y_SOURCE`.
  3. With ISOC23 on, glibc defines const-correctness **overload macros** that
     expand to `_Generic(...)`:
     - `wchar.h`: `wmemchr`, `wcschr`, `wcsrchr`, `wcspbrk`, `wcsstr`
     - `stdlib.h`: `bsearch`
     - `string.h`: `memchr`, `strchr`, `strrchr`, `strpbrk`, `strstr`
  4. gnulib **declares** those same functions (e.g. `wchar_t *wmemchr (...)`).
     The function-like macro substitutes the *declaration* into a `_Generic`
     expression — invalid in *any* C standard (a `_Generic` expression is not
     a declarator).
- **Trap**: a minimal repro `#define _GNU_SOURCE; #include <wchar.h>` compiles
  fine under `-std=gnu17` because the macro is defined but **never used**.
  The breakage only appears when code *declares* the overloaded function.

#### 3.2.2 Attempts tried (in order)

| # | Attempt | Result |
|---|---------|--------|
| A | Add `-std=gnu17` to gettext's AutotoolsToolchain `extra_cflags` (recipe edit) | Still failed — gnulib sources define `_GNU_SOURCE` themselves before config.h, re-enabling ISOC23 |
| B | Add `-U_GNU_SOURCE` + `-std=gnu17` to recipe | Still failed — config.h `#define _GNU_SOURCE` overrides it |
| C | Comment out `# define _GNU_SOURCE 1` in generated `config.h` (recipe edit after configure) | Fixed `_Generic`, but **broke `wcwidth`** (XSI function; needs `_GNU_SOURCE`-class macros) |
| D | Replace `_GNU_SOURCE` with `_XOPEN_SOURCE 700` + `_DEFAULT_SOURCE 1` in config.h | Fixed `_Generic` + `wcwidth`, but **broke GNU-only symbols**: `off64_t` (needs `_LARGEFILE64_SOURCE`), `strtold_l` |
| E | Try `-D_LIBC` to disable glibc's overload macros | **glibc rejects it**: `#error Applications may not define the macro _LIBC` |
| F | Post-configure patch of generated `wchar.h`/`stdlib.h`/`string.h` to `#undef` the overload macros | Patches ran **before** make regenerated the headers from `.in.h` templates → no effect (headers are created by `make`, not configure) |
| G | **Pre-configure patch of `*.in.h` templates** to insert `#undef <fn>` right after the include guard | **WORKED** — make's sed generation bakes the `#undef` into the final headers; gettext built end-to-end and pulseaudio linked |

- The successful patch (G) inserted into each template right after
  `#define _@GUARD_PREFIX@_{WCHAR,STDLIB,STRING}_H`:
  - `wchar.in.h`: `# undef wmemchr wcschr wcsrchr wcspbrk wcsstr`
  - `stdlib.in.h`: `# undef bsearch`
  - `string.in.h`: `# undef memchr strchr strrchr strpbrk strstr`
- **Status**: reverted (see §4). Do not re-apply to downloaded recipes.

#### 3.2.3 Recipe-editing pitfalls hit along the way (for the record)

- `import glob` inside `build()` **shadowed** the module-level `glob` import,
  causing `NameError: cannot access free variable 'glob'`.
- Editing the recipe changes its RREV → conan builds into a **new** build-folder
  hash (e.g. `gette98443cf72a1ed` → `gette9019c5b64659a`), so stale patched
  headers lingered in old folders.
- Shell heredocs: use `python3 - <<'PY'` (quoted delimiter) when you need the
  literal `$` — otherwise bash expands `$B` before python sees it.

## 4. Decision: revert the gettext recipe workaround

The gettext workaround (attempt G) *did* produce a working build, but it
required editing the downloaded gettext recipe and source templates in the
Conan cache. That is explicitly off-limits (§0).

Actions taken to restore pristine state:
1. Restored `/home/hellscoffe/.conan2/p/gettedbdc9308242d5/e/conanfile.py`
   from `conanfile.py.bak` (pristine — verified it had no C17/GNU_SOURCE/
   `#undef` edits).
2. `conan remove "gettext/0.26*" -c` — removed the recipe **and** all binaries
   from the cache; next install re-downloads pristine gettext from conancenter.
3. Deleted all patched gettext build folders under `~/.conan2/p/b/gette*/`.
4. Kept the *project-level* (allowed) fix: `-std=gnu17` via install conf.

**Net status**: gettext 0.26 remains **unbuildable** on this toolchain without
touching the downloaded recipe. The full conan install therefore does **not**
complete. This is a genuine upstream incompatibility (glibc 2.40 C23 overload
macros vs. gnulib declarations), not a project bug.

## 5. Category: project code decisions & invariants

- **DB credentials**: `BKSYS_DB_PASSWORD` is env-only, required. Never add a
  `password` key to `config.json`. Precedence: env > config.json > default.
- `ConfigurationManager/` is live and wired into `CMakeLists.txt`; keep its
  `find_package(nlohmann_json)` so it builds standalone.
- `DBHandler/` is **not** wired into the build (skeleton/stub). Don't assume it
  compiles.
- `src/server.cpp`, `src/connection.cpp` are dead Asio tutorial copies, not
  compiled.
- imgui `bindings/` files are generated by `conanfile.py` — don't hand-edit.
- `.github/worflows/ci.yml` (typo) is stray; only `.github/workflows/ci.yml`
  is live; CI test job runs only on the `development` branch.

## 6. Category: operational mishaps (sessions/commands)

- Long-running conan installs: use `nohup ... &` with a log file, then poll
  `pgrep -f "conan install"`. The 120 s bash-tool timeout kills foreground
  sleeps; backgrounded installs survive.
- Early full installs were run with SDL feature trims
  (`-o "sdl/*:opengl/wayland/x11/pulse/alsa/jack=False"`) to get a partial
  binary — do **not** repeat the trims; the goal is the full backend set.
- Log trail (for archaeology): `/tmp/opencode/conan_install_final{,2..10}.log`
  and `graph.json`.

```bash

    -pr:b=conan_profiles/override_gettext --build=missing \
    -c tools.build:cflags="[\"-std=gnu17\"]"
```
